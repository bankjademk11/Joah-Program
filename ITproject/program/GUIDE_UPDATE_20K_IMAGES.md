# คู่มือการอัปเดตและเพิ่มรูปภาพสินค้า 20,000+ รูป (Joah Lens Visual Search)

เอกสารนี้จัดทำขึ้นเพื่อเป็นแนวทางขั้นตอนปฏิบัติ (SOP) ในการเพิ่มหรืออัปเดตฐานข้อมูลรูปภาพสินค้าสำหรับระบบ **Joah Lens (AI Visual Search)** เมื่อมีสินค้าระลอกใหม่เข้ามา (เช่น เพิ่มอีก 19,000+ รายการ)

---

## 📌 สรุปภาพรวมความสามารถของระบบ
- **โมเดล AI**: Meta DINOv2 (`dinov2_vits14`) ขนาด 384 dimensions
- **ระบบค้นหา**: FAISS Index (Facebook AI Similarity Search)
- **สเกล 20,000 รูป**:
  - ใช้ RAM เก็บ Index เพียง **~30 - 35 MB**
  - ใช้เวลาค้นหาต่อ 1 ครั้งเพียง **0.005 วินาที (5-10 ms)**
  - หน้าเว็บโหลดเร็วเท่าเดิม 100% เพราะดึงเฉพาะ 10 อันดับแรกที่ค้นเจอ

---

## 🛠 ขั้นตอนที่ 1: เตรียมรูปภาพสินค้า
1. **การตั้งชื่อไฟล์รูปภาพ:**
   - ตั้งชื่อไฟล์ตาม **Barcode** ของสินค้า เช่น `8851234567890.jpg` หรือ `8851234567890.webp`
2. **อัปโหลดภาพขึ้นระบบ:**
   - นำรูปภาพอัปโหลดเข้า Supabase Storage Bucket: `product-images` (เพื่อให้หน้าบ้านและระบบอื่นๆ ดึงรูปไปแสดงได้)
   - หรือบันทึกลงในโฟลเดอร์ภาพสำหรับประมวลผล เช่น `./images/`

---

## ⚡ ขั้นตอนที่ 2: การสร้าง Vector Embeddings & FAISS Index

เมื่อมีรูปภาพใหม่ 19,000+ รูป ให้ทำการประมวลผลแปลงรูปภาพเป็น Vector Index

### ทางเลือกที่ A: รันผ่าน Google Colab (แนะนำที่สุด - เร็ว ฟรี ไม่กินแรงเครื่อง)
1. อัปโหลดโฟลเดอร์รูปภาพ หรือดึงรูปจาก Supabase Bucket เข้า Google Colab
2. เปิดใช้งาน Hardware Accelerator เป็น **T4 GPU** (ฟรี)
3. รันโค้ดสกัด Embedding ด้วยโมเดล DINOv2:
   - ด้วย GPU T4: ภาพ 20,000 ภาพจะใช้เวลาเพียง **~10 - 20 นาที**
4. ดาวน์โหลดไฟล์ผลลัพธ์ 2 ไฟล์ออกมา:
   - `product_embeddings.npy`
   - `product_index.faiss`

### ทางเลือกที่ B: รันในเครื่องตัวเอง (Local Machine)
- หากเครื่องมี GPU (Nvidia RTX): ใช้เวลาประมาณ 15 - 30 นาที
- หากใช้ CPU ล้วน: ใช้เวลาประมาณ 1.5 - 2.5 ชั่วโมง (สามารถรันเปิดทิ้งไว้ข้ามคืนได้)

---

## 🚀 ขั้นตอนที่ 3: อัปเดตขึ้นเซิร์ฟเวอร์ (Hugging Face Spaces)

หลังจากได้ไฟล์ Index ชุดใหม่ 2 ไฟล์ (`product_embeddings.npy` และ `product_index.faiss`):

1. นำไฟล์ทั้ง 2 ไปวางทับไฟล์เดิมในโฟลเดอร์:
   ```
   ITproject/program/index_data/
   ├── product_embeddings.npy
   └── product_index.faiss
   ```
2. ทำการ Git Push ขึ้น Hugging Face Space (หรือเซิร์ฟเวอร์ที่รัน API):
   ```bash
   git add ITproject/program/index_data/
   git commit -m "update: refresh FAISS index with 20k product embeddings"
   git push origin main
   ```
3. เซิร์ฟเวอร์จะทำการ Reload อัตโนมัติ (ใช้เวลาประมาณ 30 วินาที - 1 นาทีในการโหลด Index ใหม่เข้า Memory)

---

## 🎯 ขั้นตอนที่ 4: ตรวจสอบความถูกต้อง
1. เปิดหน้าเว็บ **Joah Lens** บนคอมพิวเตอร์หรือมือถือ
2. ทดลองถ่ายรูปหรืออัปโหลดรูปสินค้าจากล็อตใหม่ที่เพิ่งเพิ่มเข้าไป
3. ตรวจสอบว่าระบบค้นพบรายการสินค้า, แสดงระดับความเหมือน (Match %), ชื่อสินค้า และราคาสินค้าถูกต้องสมบูรณ์

---

## 💡 ทริคและข้อควรจำ (Pro Tips)
1. **Incremental Update (อัปเดตเฉพาะรูปใหม่):**
   - ใน script สามารถใส่ logic เช็ค barcode ที่มีอยู่แล้วใน index เดิม หากมีแล้วให้ข้ามไม่ต้องคำนวณซ้ำ จะทำให้รอบถัดๆ ไปใช้เวลาเพียงไม่กี่นาที
2. **ขนาดไฟล์รูปภาพ:**
   - ก่อนส่งเข้า AI ไม่จำเป็นต้องใช้รูปขนาดใหญ่หลาย MB ตัวโมเดล DINOv2 จะย่อรูปเหลือขนาดประมาณ 224x224 หรือ 518x518 พิกเซลเพื่อคำนวณอยู่แล้ว การใช้รูประดับความละเอียดกลางๆ (~100-300 KB) จะทำให้การอ่านไฟล์และประมวลผลไวกว่ามาก
3. **ความเสถียรของหน้าบ้าน:**
   - หน้าเว็บ [VisualLensSearch.jsx](file:///c:/Users/ideapad%20sl%203i/OneDrive/Desktop/JoahToolsHelp/warehouse-validator/src/components/Tools/VisualLensSearch.jsx) จะไม่มีทางหน่วงลง แม้ในอนาคตสินค้าจะเพิ่มเป็น 50,000 หรือ 100,000 รายการ เพราะขั้นตอนการคำนวณความเหมือนเกิดขึ้นที่ Server/FAISS และส่งเฉพาะผลลัพธ์ 10 รายการที่ดีที่สุดกลับมาที่เว็บเท่านั้น
